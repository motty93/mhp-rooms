# 部屋一覧の表示領域改善

**実装時間**: 約15分（2026-08-20）

## 概要

部屋数が少ないとき、部屋一覧の表示領域が縮んでフッターがファーストビュー内に大きく入り込み、窮屈に見える問題を改善した。

## 原因

- `base.tmpl` は `body: min-h-screen flex flex-col` + `main: grow` の構成のため、コンテンツが短いページでは body がちょうど 100vh になり、背の高いフッター（3 カラム + リンク 9 本 ≒ 350px 前後）が初期表示の下部を占めていた
- モバイルでは部屋一覧セクションに `min-h-[calc(100vh-200px)]` があってフッターを押し下げていたが、`md:min-h-0` によりデスクトップでは無効化されていた

## 変更内容

`templates/pages/rooms.tmpl` のみ変更。

1. ページ全体のラッパー `<div x-data="rooms()">` に `min-h-[calc(100vh-4rem)]` を付与
   - 4rem は固定ヘッダーの高さ（`h-16`、`main` の `pt-16` と対応）
   - これにより部屋一覧ページのコンテンツが常にビューポートの高さいっぱいに広がり、フッターはスクロールした先に表示される
2. 部屋一覧セクションのモバイル専用ハック `min-h-[calc(100vh-200px)] md:min-h-0` を削除
   - ラッパー側の min-height が全ブレークポイントをカバーするため冗長になった

## 工夫した点

- セクション単位ではなくページラッパーに最小高さを持たせることで、マジックナンバーをヘッダー高（4rem）のみに抑えた（セクション単位だと上部のタイトル・フィルタ領域の高さを引き算する必要があり、内容の増減で崩れやすい）
- `base.tmpl` の `main` に付ける案（全ページ共通化）も検討したが、影響範囲がサイト全体に及ぶため、今回は指摘のあった部屋一覧ページに限定した（他ページでも同様の要望が出たら `main` 側への移動を検討する）
