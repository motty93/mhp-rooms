# 自分のプロフィール画面を新レイアウトに統一

- 実装日: 2026-09-11
- 所要時間: 19:25 〜 19:34

## 背景

公開プロフィール `/users/{uuid}` は `templates/pages/user_profile.tmpl` + `templates/components/profile_card_content.tmpl` で新レイアウト（カバー帯＋横長プロフィールカード＋下部タブ）になっていたが、自分のプロフィール `/profile` は旧テンプレート `templates/pages/profile.tmpl`（2カラム、`profile_view` 部分テンプレート、緑のオンライン点、タブ最低高300px）のままだった。`UserHandler.Show` はログイン中に自分の `/users/{uuid}` を開くと `/profile` へリダイレクトするため、自分のプロフィールでは新レイアウトを確認する手段がなかった。

## 変更内容

- `internal/handlers/profile.go`
  - `Profile()` を書き換え、`user.go` の `UserProfileData` を組み立てて `user_profile.tmpl` を描画するようにした
  - `Rooms, RoomsPagination` 以外の共通部分（`IsOwnProfile`, `IsAuthenticated`, `RelationStatus`, `ActivityCount`, `FollowerCount`, `FavoriteGames`, `PlayTimes`）を組み立てる非公開ヘルパー `ownProfileData(user *models.User) UserProfileData` を新設し、`Profile()` と `ViewProfile()` の両方で使うようにした
  - `ViewProfile()`（`/profile/view`、編集のキャンセル・保存後に htmx が `#profile-card-content` に読み込む）を `ownProfileData` + `profile_card_content` 部分テンプレートの描画に変更
- `templates/components/profile_card_content.tmpl`
  - アクションエリアの分岐を `{{ if .IsOwnProfile }}` → 編集ボタン、`{{ else if .IsAuthenticated }}` → フォロー・通報ボタン、という排他分岐に変更
  - 編集ボタンは `hx-get="/profile/edit"` / `hx-target="#profile-card-content"` / `hx-swap="innerHTML"` とし、見た目は `follow_buttons.tmpl` の「フォローする」ボタンと同じクラス構成（`min-h-11`、`focus-visible` リング付き）に合わせた
- `templates/components/profile_edit_form.tmpl`
  - ルート要素のクラスを `flex flex-col items-center` から `mx-auto flex w-full max-w-2xl flex-col items-center p-6 sm:p-8` に変更し、外側パディングのない新カードの中でも自然に見えるようにした（`x-data` / `data-init-*` / `x-init` / キャンセルボタンの `hx-get="/profile/view"` は変更なし）
- `content/info/2026-09-01-september-update.md`
  - 「公開プロフィール画面のレイアウトを改善」の改善内容に「自分のプロフィール画面も同じレイアウトになり、『プロフィールを編集』ボタンから編集できます」を追記（`summary` と `updated` は変更していない。リリース時に更新する）
- `CLAUDE.md`
  - 「類似実装箇所との整合性確認」の例示を `templates/pages/profile.tmpl` から `templates/pages/user_profile.tmpl` に修正（削除したファイルを指していたため）

### `static/js/profile.js` の確認

`returnToProfileView()` は `hx-get`/`htmx.ajax` の対象を `#profile-card-content`（汎用のコンテナID）に固定しているだけで、`profile_view.tmpl` 固有のDOM（緑のオンライン点など）には依存していない。`profileEditForm()` の `data-init-*` 読み込みや `saveProfile()` / `uploadAvatar()` も同様に汎用的で、テンプレート差し替えの影響を受けない。変更不要と判断した。

## 今後の作業・改善点

- 編集フォーム（`profile_edit_form.tmpl`）自体の見た目はまだ旧デザインのまま（グレー背景の入力欄など）。新カードの余白には合わせたが、新レイアウトのトーンに合わせた作り直しは別タスクとする
- 自分のプロフィールの `FollowerCount` は、これまで `Profile()` 内にあった「開発環境では20人固定」というフォールバックを廃止し、公開プロフィールと同じ `getFollowerCount()`（フォロー取得失敗時は0人）に統一した。環境で挙動を分けない方針（CLAUDE.md）にも合致する
- リリースは通常どおり main → staging → production で行う
