# プロフィールタブ領域の最低高を拡大

- 実装日: 2026-09-11
- 所要時間: 17:08 〜 17:16

## 概要

ユーザーがローカル環境（部屋5件・アクティビティ0件のプロフィール）で確認したところ、「作成した部屋」タブから空の「アクティビティ」タブへ切り替えるとタブ領域が縮み、フッターが上に動く問題が報告された。原因はタブ領域の最低高（PC 380px / スマホ 320px）が部屋カード数件分より低く、レコードがあるタブと空のタブで高さが大きく違うことだった。対応方針は4案（最低高を部屋5件分に広げる／1ページ5件に変更して最低高もそろえる／JSで描画済みの最大高さを保持／固定高と内側スクロール）を比較し、ユーザーが「最低高を部屋5件分に広げる（CSSのみ）」を選択した。

## 計測

Playwright で、ローカルの部屋5件・アクティビティ0件のプロフィールを計測した。

- 変更前: PC 1280px幅で部屋タブの領域642px → 空のアクティビティで380px、フッターが262px上に移動。スマホ390px幅で742px → 320px、フッターが422px上に移動
- 部屋カード1件の高さはPCで90〜126px（説明文の有無で変わる）、スマホで110〜170px
- 変更後: PCで642px → 640px、フッターの移動は2px。スマホでは742px → 480pxで移動262px（スマホは控えめな最低高にしたため縮む余地を残している）

## 修正

- `templates/pages/user_profile.tmpl`: タブ領域の最低高を `min-h-[320px] sm:min-h-[380px]` から `min-h-[480px] sm:min-h-[640px]` へ変更（PCは部屋カード5件分、スマホは控えめに480px）
- `templates/components/user_profile_rooms.tmpl` と `templates/components/profile_activity.tmpl`: 空状態の枠の最低高を `min-h-[260px] sm:min-h-[310px]` から `min-h-[448px] sm:min-h-[584px]`（領域の最低高からパディングを引いた値）へ変更し、空状態のカードが領域の中央に来るようにした
- `internal/handlers/profile_tabs_render_test.go`: `TestRenderUserProfileIncludesDetailsAndAccessibleTabs` の最低高アサーションを `sm:min-h-[640px]` に更新
- 1ページの件数（20件）とページネーションは変更していない

## 検証

- `npx prettier --check` を3テンプレートに実行して成功
- `go test ./internal/handlers/` 成功
- 起動中のローカルサーバーはテンプレートをキャッシュしていて再起動は行わない運用のため、Playwrightでローカルページを読み込んだ上で新しいクラスと新しい空状態のHTMLをDOMに適用して計測した（上記「計測」の変更後の数値）
- PC幅のスクリーンショットで、空状態のカードが640pxの領域の中央に表示されることを確認した

## 更新情報について

- `content/info/2026-09-01-september-update.md` は変更しない。既存の「タブを切り替えても画面全体の高さが大きく変わらないようにしました」の記載内容と一致する調整で、`updated` を進めると全ユーザーに未読通知が再表示されるため

## 今後の作業・改善点

- 部屋が6件以上あるプロフィールでは、空のタブへ切り替えると領域が縮む余地が残る。気になる場合はJSで描画済みの最大高さを保持する方式を検討する
- スマホは最低高を控えめ（480px）にしているので、実機で空のプロフィールの余白が気になれば調整する
- リリースは通常どおり main → staging → production で行う
