# 公開プロフィールのアバター重なり修正

- 実装日: 2026-09-11
- 所要時間: 16:55 〜 17:05

## 概要

2026-09-11 の本番リリース（Production Release 20260911、PR #223）直後、公開プロフィール画面でアバター画像の上部がカバー（ヘッダーの濃紺のグラデーション帯）に隠れ、円の上側が水平に切れて見える不具合をユーザーから報告を受けた。修正対象は `templates/components/profile_card_content.tmpl` のアバター `<img>` 1 箇所で、クラスに `relative z-10` を追加する 1 行の変更で解消した。回帰テストとして `internal/handlers/profile_tabs_render_test.go` の `TestRenderUserProfileIncludesDetailsAndAccessibleTabs` に、アバター `<img>` の class を確認するアサーションを追加した。

## 原因

- カバーの `<div>` は装飾用の円を `absolute` で配置するために `relative`（position: relative）を持つ
- アバター `<img>` は `-mt-7` / `sm:-mt-10` の負マージンでカバーに重ねていたが、position 指定のない通常フロー要素だった
- CSS の描画順では position 指定のある要素（z-index auto）が通常フローの要素より後に描画されるため、DOM 上で後にあるアバターでもカバーが上に描画され、負マージンで重なった約 40px（モバイルでは約 28px）が隠れていた
- モックアップ `docs/mockups/user_profile.html` では `.profile-cover` に position 指定がなく、装飾円は親の `.profile-hero` を基準に配置しているため、この問題が起きていなかった

## 修正

- アバター `<img>` に `relative z-10` を付け、カバーより前面のスタッキング順で描画されるようにした
- カバー側の `relative` / `overflow-hidden` は装飾円の配置に必要なため変更していない

## 検証

- `npx prettier --check templates/components/profile_card_content.tmpl` 成功
- `go test ./internal/handlers/` 成功（追加したアサーションを含む）
- 追加したアサーションは、修正前のテンプレートに戻すと失敗することを確認済み
- `go test ./...` 成功
- 本番の HTML を取得して同じクラス変更を当てたものを headless Chrome（1280px 幅、devicePixelRatio 2）で描画し、アバターの円がカバーの上に完全に表示されること、モックアップと同じ見た目になることを確認した
- 修正前の本番画面を同条件で描画し、円の上部がカバーに隠れていることも再現している

## 更新情報について

- `content/info/2026-09-01-september-update.md` は変更していない。今回はリリース済み機能の表示不具合の修正であり記載内容に変化がなく、`updated` を進めると全ユーザーに未読通知が再表示されるため対象外とした

## 今後の作業・改善点

- テンプレートで負マージンによる重なりを使う場合は、重ねる側に `relative z-10` などのスタッキング指定を必ず付ける
- 前回（01 のログ）の Playwright 確認は横スクロールとタブ 1 行の確認が中心で、カバーとアバターの重なりまでは見ていなかった。今後はモックアップと同じ位置のスクリーンショットを並べて比較する
- リリース手順は通常どおり main → staging → production で行う（本番は staging でビルドした latest イメージを使うため、staging ビルドの完了を待つ）
