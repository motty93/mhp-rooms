# 部屋の解散・自動削除時にメンバーへお知らせ（Issue #68 追加分）

**実装時間**: 約 15 分（17:20〜17:35 頃）

## 概要

お知らせ機能 MVP（`03_お知らせ機能MVP.md`）の補足として、部屋が解散・自動削除されたときに**参加していたメンバー（ホスト以外）**にもお知らせが届くようにしました。ユーザーからの「部屋が削除・閉じられたときにもお知らせが行くか」という確認を受けての追加です。

## 追加した通知

| イベント | 通知先 | タイトル |
|---|---|---|
| ホストが部屋を解散 | 参加中のメンバー（ホスト以外） | 部屋「X」が解散されました |
| 一定期間活動がなく自動削除 | 参加中のメンバー（ホスト以外）※ホスト向けは既存 | 参加していた部屋「X」が自動的に削除されました |

募集の締め切り / 再開（`is_closed`）は、参加済みメンバーには実害がなく頻繁に切り替わることもあるため通知しない方針にしました（ユーザーと合意）。

## 実装内容

| ファイル | 変更 |
|---|---|
| `internal/models/notification.go` | `NotificationRoomDismissed` 定数 |
| `internal/services/notification_service.go` | `NotifyRoomDismissedToMembers` / `NotifyRoomAutoDismissedToMembers`（共通の `notifyMembers` でホストを除外、一部失敗しても続行） |
| `internal/handlers/rooms.go`（DismissRoom） | 解散するとメンバーが退出状態になるため、**解散前に `GetRoomMembers` で取得**してから解散後に通知 |
| `internal/services/room_cleanup_service.go` | 同様に自動削除前にメンバーを取得し、ホスト向けに加えてメンバーへも通知 |
| `internal/services/notification_service_test.go` (新規) | `repository.Repository` にフェイクの `NotificationRepository` を差し込み、ホスト除外・件数・内容を検証 |
| `content/info/2026-08-18-august-update.md` | 届くお知らせの一覧に追記 |

## 特に注意した点

- `DismissRoom` はトランザクション内で全メンバーを `left` にするため、通知対象は必ず**解散前に取得**する
- キック済み・退出済みのメンバー（非アクティブ）には届かない（`GetRoomMembers` はアクティブのみ返す）
- お知らせ作成の失敗は解散処理の成否に影響させない（ログのみ）
